# ECサイト運営者向け GitHub Actions ワークフローガイド

このドキュメントでは、コイン販売ECサイトの日常運営で使用するGitHub Actionsを、業務フローに沿って説明します。

---

## 業務フロー概要

```
┌─────────────────────────────────────────────────────────────────────┐
│  1. 商品仕入れ（仕入れ先から商品情報を取得）                           │
│     └─ [BS1] 商品一覧取得                                            │
├─────────────────────────────────────────────────────────────────────┤
│  2. 商品採用（販売する商品を選定）                                     │
│     └─ スプレッドシートで採用フラグを「採用」に変更                    │
├─────────────────────────────────────────────────────────────────────┤
│  3. カラーミー登録（採用商品をECサイトに登録）                         │
│     └─ [BS2] 採用商品をカラーミーに登録                               │
│     └─ [BS4] Upload Product Images                                   │
├─────────────────────────────────────────────────────────────────────┤
│  4. 日常運用（価格・在庫の定期更新）                                   │
│     └─ BS3 Price Stock Update（4時間ごと自動実行）                    │
│     └─ Price Check（4時間ごと自動実行）                               │
└─────────────────────────────────────────────────────────────────────┘
```

---

## 1. 商品仕入れフェーズ

### [BS1] 商品一覧取得（新規・価格・AI生成）
**ファイル**: `fetch-bullionstar-products.yml`

| 項目 | 内容 |
|------|------|
| **目的** | Bullionstarから商品情報を自動取得し、スプレッドシートに保存 |
| **対象シート** | ブリオンスター商品ページ一覧 |
| **実行タイミング** | 自動（6時間ごと）/ 手動 |
| **主な処理** | 新商品の取得、価格更新、AI商品名生成 |

**使い方**:
1. 自動実行を待つ、または手動で「Run workflow」をクリック
2. 取得完了後、スプレッドシートで新商品を確認

---

### Fetch Supplier Prices
**ファイル**: `fetch-suppliers.yml`

| 項目 | 内容 |
|------|------|
| **目的** | 複数の仕入れ先サイトから最新価格を取得 |
| **実行タイミング** | 自動（4時間ごと）/ 手動 |

---

## 2. 商品採用フェーズ

このフェーズはスプレッドシート上で手動で行います。

**作業内容**:
1. 「ブリオンスター商品ページ一覧」シートを開く
2. 販売したい商品のA列（採用フラグ）を「採用」に変更
3. 必要に応じて商品名やカテゴリを調整

---

## 3. カラーミー登録フェーズ

### [BS2] 採用商品をカラーミーに登録
**ファイル**: `bs-register-adopted-products.yml`

| 項目 | 内容 |
|------|------|
| **目的** | 採用フラグが「採用」の商品をカラーミーに新規登録 |
| **対象シート** | ブリオンスター商品ページ一覧 |
| **トリガー** | A列 = 「採用」 |
| **実行タイミング** | 手動のみ |

**オプション**:
| オプション | 説明 |
|-----------|------|
| `dry_run` | チェックすると実際の登録なし（テスト用） |
| `limit` | 処理件数を制限（例: 5件だけテスト） |
| `skip_images` | 画像アップロードをスキップ |

**使い方**:
1. スプレッドシートで採用商品を選定
2. GitHub Actionsで「Run workflow」をクリック
3. 完了後、B列が「登録済」に更新される

---

### [BS4] Upload Product Images
**ファイル**: `upload-images.yml`

| 項目 | 内容 |
|------|------|
| **目的** | 登録済み商品の画像をカラーミーにアップロード |
| **実行タイミング** | 手動のみ |

**使い方**:
- [BS2]で画像アップロードをスキップした場合に使用
- 画像のみを後からアップロードしたい場合に使用

---

### [BS2] 欠損データ補完（AI生成・為替）
**ファイル**: `bs-supplement-ai-content.yml`

| 項目 | 内容 |
|------|------|
| **目的** | 商品名や説明文のAI生成、為替レート更新 |
| **実行タイミング** | 手動のみ |

## 4. 日常運用フェーズ（自動実行）

### BS3 Price Stock Update
**ファイル**: `bs3-update-prices.yml`

| 項目 | 内容 |
|------|------|
| **目的** | 検討中の商品の価格・在庫状況を更新 |
| **対象シート** | ブリオンスター商品ページ一覧 |
| **実行タイミング** | 自動（JST 8, 12, 16, 20, 0, 4時）/ 手動 |
| **デフォルト対象** | 検討中の商品のみ |

**オプション**:
| オプション | 説明 |
|-----------|------|
| `exchange_type` | 為替種類（クレカ / Wise） |
| `pending_only` | 検討中の商品のみ対象（デフォルト: true） |
| `dry_run` | 実際の更新なし（テスト用） |
| `limit` | 処理件数制限 |

---

### Price Check
**ファイル**: `price-check.yml`

| 項目 | 内容 |
|------|------|
| **目的** | 登録済み商品の価格をチェックし、カラーミーに同期 |
| **実行タイミング** | 自動（4時間ごと）/ 手動 |

---

### ColorMe Product Management
**ファイル**: `colorme-management.yml`

| 項目 | 内容 |
|------|------|
| **目的** | カラーミー商品のフルサイクル管理（ダウンロード→価格取得→同期） |
| **対象シート** | 新カラーミー商品管理 |
| **実行タイミング** | 手動のみ |

**処理の流れ**:
1. カラーミーから全商品をダウンロード
2. 仕入れ先URLから最新価格を取得
3. A列=「更新」の商品をカラーミーに同期

## トラブルシューティング

### スケジュール実行が動かない場合
1. GitHub Actionsページでワークフローが「active」になっているか確認
2. 一度手動実行（Run workflow）を行う
3. 数分〜15分の遅延は正常

### 商品が登録されない場合
1. スプレッドシートのA列が「採用」になっているか確認
2. 商品IDが空でないか確認
3. dry_runがオフになっているか確認
