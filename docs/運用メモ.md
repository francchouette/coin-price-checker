## 1. SEO項目の一括編集・反映

### 背景

カラーミーAPI（`/products/{id}.json`）は **SEO項目を扱えない**（title_tag / meta_description / meta_keywords のフィールドが存在しない）。そのため、シート→API同期では反映できず、**CSV経由でカラーミー管理画面にインポート** する運用になる。

### 前提

- カラーミーのCSVインポートは **空欄も上書きしてしまう** 仕様
- 全列を埋めたCSVが必要なので、ベースCSVにシート側の編集を重ねて出力する
- 内容に変更がない商品は無視される（カラーミー側の仕様）

### 手順

#### 1-1. カラーミーから最新CSVをダウンロード

1. カラーミー管理画面（https://admin.shop-pro.jp）にログイン
2. 「商品一括登録」→ CSVエクスポート機能で全商品CSVをダウンロード
3. ダウンロードしたCSVはUTF-8形式（Google Sheetsで扱いやすい）

#### 1-2. Googleスプレッドシートに日付付きシート名でインポート

Google スプレッドシートの「コイン価格チェック」ブックを開き、以下を実行:

1. 新規シートタブを追加
2. シート名を `カラーミーCSV_YYYYMMDD`（例: `カラーミーCSV_20260501`）に変更
3. ファイル → インポート → CSVファイルをアップロード
4. インポート場所: 「新しいシートとして挿入」は選ばず、「現在のシートを置き換え」で今作った日付シートへ展開

#### 1-3. 新カラーミー商品管理シートでSEO列を一括編集

以下3列を編集:
- **BO列**: ページタイトル
- **BP列**: メタディスクリプション
- **BQ列**: メタキーワード

Googleスプレッドシートの一括編集機能（ドラッグ、フィルター、関数等）で効率的に編集できる。

#### 1-4. ドライランで差分確認

```bash
python -m src.export_colorme_csv --base-sheet カラーミーCSV_20260501 --dry-run
```

**確認ポイント:**
- 上書き対象件数が想定どおりか
- 「シートのみに存在」の件数（CSV未登録の新商品） → スキップされる
- 「重複商品ID」の警告が出ていないか
- 変更サンプルで値が正しいか

#### 1-5. CSV出力を実行

```bash
python -m src.export_colorme_csv --base-sheet カラーミーCSV_20260501
```

出力先: `/Users/user/coin-price-checker/exports/colorme_import_YYYYMMDD_HHMMSS.csv`

#### 1-6. カラーミー管理画面からCSVをアップロード

1. カラーミー管理画面の「商品一括登録」メニューを開く
2. 出力されたCSVファイルを選択してアップロード
3. アップロード結果を確認（変更なしの商品はスキップされる）

#### 1-7. 反映確認

カラーミー上の任意の商品ページでSEO項目が更新されているか確認。

### 注意事項

- **シートの空欄はスキップされる**（CSVの既存値を維持）
- **数式エラー値（`#N/A`, `#REF!`等）はスキップされる**
- **シート側だけに存在する商品はCSV出力に含まれない**（警告表示）
- **SEO以外の項目も同時に更新したい場合**: `--fields seo,price,name` のように追加指定可能
  - 利用可能: `seo`, `price`, `name`, `description`, `model`, `stock`, `shipping`

### 参考: CSV出力スクリプトの全オプション

```bash
python -m src.export_colorme_csv --help
```

## 2. 新商品のカラーミー登録後にシートに反映する

### 手順

採用フラグをブリオンスター商品ページ一覧シートで「採用」にした商品を、カラーミー登録 → シート反映まで進める流れ。

1. **採用フラグを設定** - ブリオンスター商品ページ一覧シートのA列を「採用」に
2. **カラーミー登録を実行** - ダッシュボードの「カラーミー登録」ボタン、または:
   ```bash
   python -m src.register_adopted_products
   ```
   → カラーミーAPIに登録、ブリオンスター商品ページ一覧シートのB列・E列が更新される
3. **API→シートで新カラーミー商品管理シートに反映** - ダッシュボードの「API→シート」ボタン、または:
   ```bash
   python -m src.download_colorme_products --verbose
   ```
   → 新カラーミー商品管理シートの末尾に新商品の行が追加される

### 注意事項

- `register_adopted_products.py` は新カラーミー商品管理シートには書き込まない（設計上別プロセス）
- 必ずAPI→シートを実行してシートに反映させる
- シートから行を削除してもカラーミーAPIに存在すれば次回API→シートで復活する

## 3. 仕入れ先URL（J列）の自動補完

### 背景

新カラーミー商品管理シートのJ列（仕入れ先URL）は、API→シートでは書き込まれない（手動入力 or 自動補完が必要）。K列以降は商品仕入れ先一覧シートからINDEX/MATCHで自動取得されるため、J列さえ埋まれば他の列は自動的に反映される。

### 手順

```bash
# ドライラン
python -m src.fill_supplier_url --dry-run

# 本実行
python -m src.fill_supplier_url --verbose
```

商品仕入れ先一覧シートのS列（カラーミー商品ID）→ C列（仕入れ先URL）をマップとし、新カラーミー商品管理シートのG列（カラーミー商品ID）と突合してJ列を埋める。

### 注意事項

- 商品仕入れ先一覧に存在しない商品（古いカラーミー商品等）は手動入力が必要
- 既にJ列に値がある行はスキップ（`--overwrite` で強制上書き可）

## 4. 不要商品を完全削除する手順

### 重要: 削除の順序

```
1. 先にカラーミー管理画面から商品を削除
    ↓
2. 次にシートから行を削除
```

### 理由

シートから先に削除しても、次回「API→シート」実行時にカラーミーAPI側に残っていれば **シートに復活** します（`download_colorme_products.py` はカラーミーAPIを基準に新規商品をシートに追加する設計）。

### 手順

1. **カラーミー管理画面で商品を削除**
   - https://admin.shop-pro.jp にログイン
   - 該当商品を選択して削除
2. **新カラーミー商品管理シートから該当行を削除**
   - 商品ID（G列）を目安に該当行を探して行ごと削除
3. **ブリオンスター/APMEX商品ページ一覧シートも必要に応じて調整**
   - A列（採用フラグ）を「未採用」に変更、または行ごと削除

## 5. Bullionstar .us URLの扱い

### 背景

`bullionstar.us`（アメリカ版 Bullionstar）は **米国倉庫発送のみ** のため、日本からは購入不可。

### 自動処理（2026-04-24より）

- `bullionstar_products.py`: 商品取得時に SALES_LOCATIONS から USA を除外済み → 今後 .us URLはシートに追加されない
- `fetch_supplier_prices.py`: 価格同期実行時に .us URLはスキップしログ表示

### 既存の .us URL 商品（13件、2026-04-24時点）

以下のように設定済み:
- B列（掲載設定）: 「掲載しない」
- C列（価格更新ON/OFF）: OFF
- N/O/P列（異常価格データ）: クリア

完全に不要になった場合は「4. 不要商品を完全削除する手順」に従ってカラーミーとシートから削除。

### 該当商品が見つかった場合の手動対応

もし今後新たに .us URL が混入した場合（手動入力など）:
1. シートの該当行のB列を「掲載しない」に変更
2. C列を「OFF」に変更
3. シート→API同期を実行してカラーミー側も非表示化

## 6. 個別送料（AW列）の運用

### ルール

- **AW列は「空欄」が正解**
- 「0」はカラーミーで **送料無料商品扱い** になり、送料無料ライン（例: 合計◯◯円以上で送料無料）が**無効化**されるため禁止
- 個別送料を設定したい商品のみ、AW列に **正の数** を入力（例: `500`）

### 自動処理の挙動

コード修正済み（2026-04-24）:

| 処理 | AW=空欄 | AW="0" | AW=正の数 |
|---|---|---|---|
| download_colorme_products（API→シート） | ✅ 空欄のまま | 発生しない | 値を書き込み |
| sync_colorme_products（シート→API） | ✅ 何もしない | ✅ 何もしない | Playwright経由で個別送料を設定 |
| export_colorme_csv（CSV出力） | ✅ CSV BD列も空欄 | ✅ CSV BD列を明示的に空欄 | CSV BD列に値 |
| register_adopted_products（新規登録） | ✅ API送信せず | ✅ API送信せず | API送信 or Playwright |

### カラーミー側の個別送料をクリアしたい場合

1. シートのAW列を空欄にする
2. `python -m src.export_colorme_csv --base-sheet XXX --fields shipping`
3. 出力CSVをカラーミー管理画面の「商品一括登録」でインポート
4. カラーミー側のBD列が空欄で上書きされる → デフォルト送料適用

### ブリオンスター/APMEX商品ページ一覧シートのBC列（個別送料）

- **BC列も空欄が正解**（同じ理由）
- 商品取得コード（`bullionstar_products.py` / `apmex_products.py`）は新規取得時にBC列を**空欄**で書き込む（2026-04-28以降）
- 既存データはクリア済（BS 2,114件 / APMEX 32,872件）

## トラブルシューティング

### CSV出力時に「シートのみに存在」警告が多い

新商品がカラーミーに未登録。先にカラーミーに登録する（`python -m src.register_adopted_products`）。

### 価格のみ同期でBY列が日時で上書きされる

過去のバグ（列ずれ）の影響なら修復済み。現在はBY列が正しくSYNC_DATETIME列として定義され、競合情報はBZ-CC列に分離されている。
